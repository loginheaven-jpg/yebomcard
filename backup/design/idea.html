읽기 앱의 주인공은
본문이다.

모드 버튼을 하단으로 내리고, 장 이동을 시트로 바꾸고, 본문을 다시 짠다. 화면 위쪽을 차지하던 도구들을 비워, 말씀이 먼저 눈에 들어오게 하는 재설계다. 오른쪽 After 화면은 실제로 동작한다.

A

지금 화면의 다섯 가지 병목

셋은 직접 지적한 문제, 둘은 읽기 앱이기에 더 중요한 문제다.

문제 01

상단 탭 과밀

모드 버튼 4개가 좁은 폭에 균등 배치돼 답답하다. 본문은 화면 절반 아래로 밀린다.

문제 02

장 이동 줄바꿈

화살표·제목·읽기·전체가 한 줄에 몰려 "잠언 4/31 장"이 깨진다. 총 장수 표기가 자리를 잡아먹는 게 원인.

문제 03

하단 버튼이 본문 가림

좌·우 하단 플로팅 버튼이 마지막 구절을 덮는다. 스크롤 끝 여백이 없다.

문제 04

본문 밀도·위계 약함

절 간격이 좁고 두 번역의 주·보조 구분이 흐려 눈이 매번 다시 판단한다. 읽기 피로의 진짜 원인.

문제 05

읽기 집중 부재

검색바·탭이 늘 떠 있어 '순수하게 읽는' 순간이 없다.

C

다섯 병목, 다섯 해법

문제 번호와 해법 번호가 1:1로 맞물린다.

1

모드 버튼 → 하단 탭바

상단 4버튼 균등 배치하단 5탭(엄지 영역)

목차·검색·읽기·책갈피·설정을 하단으로. 상단을 통째로 비워 본문을 끌어올린다. 모바일 표준 패턴이라 학습 비용이 없다.

2

장 이동 → 탭하면 열리는 시트

잠언 4/31 장 (줄바꿈)잠언 4장 ▾ + 시트

총 장수 '31'을 제목에서 떼어 얇은 진행바로 옮겼다. 제목은 한 단어로 줄어 절대 깨지지 않고, 누르면 31장 그리드가 올라온다. ‹ › 화살표로 인접 장 한 번에 이동.

3

플로팅 버튼 → 탭바로 흡수

본문 위 떠다니는 2버튼책갈피·설정 탭 + 하단 여백

책갈피(45)는 탭 배지로, 도구는 설정 탭으로 들어갔다. 본문 스크롤 끝에 넉넉한 여백을 둬 마지막 절이 무엇에도 가리지 않는다.

4

본문 위계 재설계

두 번역 평면 나열주=세리프 / 보조=들여쓰기

주 번역은 세리프·진하게, 보조 번역은 왼쪽 선으로 들여쓰고 회색으로. 절 번호는 작은 위첨자 호박색. 행간을 1.9로 키워 종이책처럼 읽힌다.

5

읽기 집중 + 소리내어 읽기

검색바 상시 노출따뜻한 종이 배경 + 오디오 플레이어

스크린을 살짝 따뜻한 아이보리로 바꿔 눈부심을 줄였다. 흩어졌던 '읽기(오디오)'는 상단 버튼 한 번으로 떠오르는 미니 플레이어로 정리. (오디오 버튼을 눌러 보세요.)

설계를 관통하는 원칙

화려함은 한 곳에만 쓰고, 나머지는 조용히 비운다.

一

본문 우선

크롬(검색·탭·도구)은 가장자리로 밀고, 화면 중앙은 늘 말씀에 내준다.

二

엄지 동선

자주 쓰는 이동·전환은 모두 하단. 한 손으로 끝까지 닿는다.

三

줄바꿈을 구조로 막기

긴 정보는 시트·진행바로 옮겨 한 줄에 욱여넣지 않는다.

四

위계가 곧 가독성

서체·색·여백으로 주와 보조를 가른다. 눈이 다시 판단하지 않게.

잠언 4장 본문은 레이아웃 시연용 자리표시다. 예봄 성경읽기 프로토타입 · 모드 통합(본문검색+주제추천→검색)과 하단 5탭 IA를 전제로 제작.
