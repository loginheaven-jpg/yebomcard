# 커스텀 보이스 성경 낭독 스튜디오

예봄성경에서 쓸 **내 목소리 성경 음원**을 로컬 GPU로 만드는 도구.
실시간 아님 — 오프라인 배치 생성 → 절 단위 파일 산출 → (추후) R2 업로드.

- 엔진: Qwen3-TTS 12Hz 1.7B Base (voice clone, ICL)
- 장비: RTX 3060 12GB / torch 2.13 cu126
- **산출 단위: 절(verse)** — 예봄성경 공유 캐시에 그대로 얹기 위함
- **1차 대상 역본: 새번역(rnksv)** — 근거는 아래 "역본 선택" 참조

## 실행

```bash
cd voice
python app.py          # → http://127.0.0.1:7860
```

## 화면 3개

| 탭 | 하는 일 |
|---|---|
| **1. 보이스** | 음원 업로드 → **자동 전사(타임스탬프)** → 구간 선택 → 참조 텍스트(원문/ASR) → 이름 저장 |
| **2. 생성** | 보이스 + 입력(성경 범위 **다중선택** / 직접 입력 / 텍스트 파일) → 예상 시간 → 작업 큐 |
| **3. 검수** | 절별 결과·일치율, 행 클릭 재생, **보류 전체 재생성**, 합본 |

### 보이스 등록에서 놓치기 쉬운 것
- **인트로를 건너뛸 것.** 실제 소재(리딩지저스)는 앞 9.74초가 브랜딩+장 안내였다. 자동 전사의 타임스탬프로 절 경계를 잡는다.
- **참조 텍스트는 `원문 넣기` 권장.** ASR은 "태초"를 "대초"로 잘못 듣는다. 오인식이 참조 텍스트에 들어가면 클로닝 품질이 떨어진다.
- 10~30초 권장.

### 검수는 왜 상시로 붙는가
생성 실패가 **확률적**이다. 같은 절·같은 설정인데 뽑을 때마다 다르다(개역 4절은 4회 중 0회 성공).
그래서 "보이스 한 번 검사"로는 안 되고 **절마다** 검수해야 한다.

```
생성 → 검수 → 불합격이면 자동 재생성(최대 N회)
              └ 상한 초과 시 "보류"로 빼고 다음 절로 진행
최종 → 사람은 "보류 목록"만 확인
```

검수 항목: ① 본문 대조(ASR 역전사) ② 길이 이상(잘림/반복) ③ 무음·절단

## 구성

| 파일 | 역할 |
|---|---|
| `app.py` | Gradio UI (얇은 층) |
| `engine.py` | 모델 싱글톤·보이스·본문조회·합성·QC (UI/CLI 공용) |
| `jobs.py` | 작업 큐·상태파일·워커·재시도·재개 |
| `prosody.py` | 끊어읽기 보정(구두점 주입·대시 정리·가변 무음) |
| `gen_verses.py` / `qc_asr.py` | CLI (UI 없이 밤새 돌릴 때) |
| `smoke_job.py` | 파이프라인 통합 점검 |
| `prep_ref.py` / `transcribe_full.py` | 참조 클립 준비(초기 1회) |

상태는 `jobs/*.json`에 남아 **앱을 껐다 켜도 이어진다**. 이미 만든 절은 건너뛴다.

## 파일럿에서 확인된 것

### 배치 크기별 속도 (개역 요일 1장)
| 배치 | RTF | 새번역 전량(87.3h) 환산 |
|---|---|---|
| 기존 | 2.61 | 9.5일 |
| 2 | 1.56 | 5.7일 |
| **4** | **0.96** | **3.5일** |
| 8 | 0.89 | 3.2일 |

→ **배치 4~8 권장** (3060 12GB에서 8까지 OOM 없음).

### 역본 선택 — 새번역으로 가는 이유
같은 조건(4회 반복)으로 어미 보존율을 측정:

| | 개역 | 새번역 |
|---|---|---|
| 어미 보존 | **25%** (3/12) | **67%** (8/12, 실패분은 ASR 오인식 '사귐→사김') |
| 구두점 | 0개 | 36개(1장) |
| 통합 테스트 최저 일치율 | 78% | **95%** |

개역은 고어 종결어미가 **현대어로 정규화**된다(`하려 함이라` → `하려 합니다`). 성경 본문 훼손이라 허용 불가.
새번역은 이미 현대어라 그 위험이 없고, 구두점이 본문에 있어 끊어읽기도 자연스럽다.
게다가 예봄성경엔 **개역·쉬운성경 사람 녹음이 이미 있고 새번역만 없다** — 필요한 곳과 안전한 곳이 일치한다.

### 본문 처리 (prosody.py)
- **개역**(구두점 0개): 연결어미 뒤 쉼표, 절 끝 종결/연결에 맞춰 마침표·쉼표 주입
- **새번역**(구두점 있음): **손대지 않음** — 덧붙이면 `합니다.,` 같은 이중 부호가 된다
- **양끝 대시 제거**: 새번역 삽입구의 닫는 `-` 가 절 끝에 남는 경우가 있다(요일 1:1, 1:2)
- 절 사이 무음: 종결 0.55초 / 연결 0.15초

> 이 변형은 **생성 입력에만** 적용한다. 예봄성경 공유 캐시 키는 `sha1(원문)` 이라 원문을 바꾸면 안 된다.

## 예봄성경 연결 (예정)

`/api/tts` 는 합성 전 R2 공유 캐시를 먼저 본다:

```
tts/v1/ko/{voiceKey}/{sha1(정제본문)}.mp3
```

생성물을 이 키로 올리면 **서버 코드 수정 없이** 서빙된다(`engine.cache_key()` 가 같은 규칙).
정제 규칙(`NOTE_RE`)은 서버와 문자 단위로 동일해야 한다 — 어긋나면 조용히 캐시 미스가 난다.

## 남은 작업
1. 톤 일관성 — 여러 장 이어들을 때 흔들림 확인
2. 고유명사·숫자 — 구약 인명/지명, 수사 검증
3. mp3 인코딩 + R2 업로드 파이프라인
4. 보이스 여러 개 운용 (전량은 대표 1개, 나머지는 자주 듣는 범위만 — 보이스당 3.5일)

## 여러 PC 로 분담 생성

새번역 전권은 1대로 약 **5.4일**(129시간)이다. PC 를 늘리면 그만큼 줄어든다.

### 반드시 지킬 것 — 보이스 지문

**참조 클립이 1초라도 다르면 음색이 미묘하게 달라져 책마다 목소리가 바뀐다.**
듣기 전에는 알아채기 어렵고, 알아챘을 땐 이미 수천 절을 만든 뒤다.
그래서 각 PC 에서 지문이 **같은지 먼저 확인**한다.

```bash
python -c "import engine; print(engine.voice_fingerprint('영희'))"
```

`voice/voices/{보이스}/` 폴더(ref.wav + meta.json)를 **파일 그대로 복사**하면 지문이 같다.
절대 2번째 PC 에서 참조 클립을 다시 잘라 등록하지 말 것.

### 2번째 PC 준비

```bash
git clone <repo> && cd yebomcard/voice
pip install torch torchaudio --index-url https://download.pytorch.org/whl/cu126
pip install gradio soundfile numpy requests faster-whisper
# qwen_tts 는 PC1 과 동일한 방식으로 설치
npm i @aws-sdk/client-s3          # 업로드용(이 패키지 하나면 된다)
```

추가로 옮길 것:
- `.env.local` (Supabase 본문 조회 + R2 업로드에 필요)
- `voice/voices/영희/` (참조음 — 지문 대조 필수)

### 작업 분담

```bash
# PC1 — 구약 (진도표 순서)
python run_plan.py --voice 영희 --start 욥기 --testament old

# PC2 — 신약 (진도표 순서)
python run_plan.py --voice 영희 --start 욥기 --testament new

# 특정 책만 (분담 미세조정)
python run_plan.py --voice 영희 --only 시편,예레미야,이사야
```

### 왜 잠금·조율이 필요 없는가

R2 키가 `tts/v1/ko/{성우}/{sha1(정제본문)}.mp3` 로 **내용 주소**다.
- 서로 다른 책 → 키가 절대 겹치지 않는다
- 실수로 같은 절을 두 번 만들어도 → 같은 키에 같은 내용이 덮여 쓰일 뿐

각 PC 가 **각자 R2 에 직접 업로드**하면 되고, 산출물을 한곳에 모을 필요가 없다
(wav 를 옮기면 수 GB, mp3 로 R2 직행이면 훨씬 가볍다).

### 분량과 소요 (실측 0.21초/자 기준)

| 구분 | 권수 | 절 | 글자 | 예상 |
|---|---|---|---|---|
| 구약 | 39 | 23,133 | 1,679,495 | **98시간** |
| 신약 | 27 | 7,942 | 532,144 | **31시간** |
| 전체 | 66 | 31,075 | 2,211,639 | 129시간 |

구약이 76% 라 단순 구약/신약 분담은 4.1일 : 1.3일로 기운다.
**PC2 가 신약을 끝내면(약 1.3일) 구약 큰 책을 넘겨받는 방식**을 권한다:

```bash
# PC2 2단계 — 뒤쪽 큰 책을 가져간다
python run_plan.py --voice 영희 --only 시편,예레미야,이사야,에스겔,민수기
```

이렇게 하면 양쪽 약 2.7일로 맞아 전체 기간이 절반이 된다.
진도표 앞쪽(욥기·창세기·출애굽기…)은 PC1 이 순서대로 만들므로
교인이 읽는 순서에는 구멍이 생기지 않는다.
