# 성경 질문 — 지난 설교를 어떻게 쓸 것인가 (설계안)

> 지휘부 질문(2026-09-18): "예봄교회 설교는 구글 드라이브에 텍스트로 저장되고 있다.
> 이것을 활용하여 질문에 대해 이전 설교 내용을 인용하거나 소개할 방법이 있을까?"
> 3개 안을 세 관점(교리 안전 · 구현 실효 · 목회 유용)으로 검증한 결과다.
> **상태: 재가 대기.** 결론은 **1단계에서 AI 에게 설교를 주지 않는다** — 앱이 카드로 따로 붙인다.

## 1. 드라이브에 실제로 무엇이 있는가 (2026-09-18 확인)

한 폴더(`1l2K2CMjvqKl6k7dTfgXM--E_L1dqavlm`)에 `YYYY년 M월 D일 주일설교.txt` 로
**50 편**이 있다(2025-07-27 ~ 2026-09-06, 빠진 주가 더러 있다). 파일 하나가 2~11 KB.
설교자가 다르면 제목에 이름이 붙는다(`… 주일설교 최병희 목사님`, `… 정용재 목사님`).

**머리글이 정해진 꼴로 들어 있다** — 이것이 이 설계의 열쇠다. 본문 구절을 사람이 이미 적어 두었으니
기계가 추측할 일이 없다.

```
날짜 : 2026년 9월 6일 주일설교
제목 : 빈 배의 축복
설교자 : 최병희 목사님
본문 : 누가복음 5:1-11
영상링크 : https://youtu.be/...

-요약-   (이미 잘 다듬어진 3~4 문단)
-적용-   (1. 2. 3. 목장에서 나눌 질문)
```

**주의 — 키 이름이 해마다 바뀌었다.** 2025 년 파일은 `설교말씀` · `설교본문` · `영상`,
2026 년 파일은 `제목` · `본문` · `영상링크` 다. 읽는 코드는 **두 이름을 모두 받아야** 하고,
못 읽은 파일은 조용히 버리지 않고 목록으로 보고해야 한다.

곁가지로 얻은 것: 설교 본문에 **VIP**(전도 대상)가 실제로 쓰인다 →
[BIBLE_QA_HOUSECHURCH.md](BIBLE_QA_HOUSECHURCH.md) 의 낱말 목록에 `VIP` 를 넣는 것이 맞다.

## 2. 세 가지 안과 판정

| | 안 | 하는 일 | 판정 |
|---|---|---|---|
| **1** | **앱이 카드로 붙인다** | 구절 → 설교 색인을 앱이 찾아, AI 답 **옆에** '이 구절을 다룬 우리 교회 설교' 카드를 그린다. AI 는 설교를 보지 못한다 | **채택(1단계)** |
| 2 | 요약을 프롬프트에 넣는다 | 맞는 설교의 `-요약-` 을 인용 블록으로 붙이고 "여기 있는 말만 우리 교회 설교로 인용하라" 고 묶는다 | 3단계에. 카드와 **함께**만 |
| 3 | 설교 전문을 검색해 넣는다(RAG) | 임베딩으로 본문을 쪼개 검색해 넣는다 | **하지 않는다** |

**1안을 택한 이유 셋.**

1. **목사님 입에 없던 말이 들어가지 않는다.** 3안·2안은 모델이 요약을 다시 요약하면서
   어투와 강조를 바꾼다. 교인은 그것을 "우리 목사님이 그러셨다" 로 읽는다.
   카드는 **제목 · 날짜 · 요약 첫 문단 · 영상 링크**를 그대로 보여 주고, 판단은 교인이 한다.
2. **답의 틀을 지킨다.** 답은 네 줄 9~14 문장에 구절 3 개까지다([BIBLE_QA_DOCTRINE.md](BIBLE_QA_DOCTRINE.md) §4).
   3천 자 설교를 밀어 넣으면 이 틀이 무너진다.
3. **돈도 시간도 들지 않는다.** 게이트웨이에 임베딩 창구가 없어 3안은 새 외부 의존이 생긴다.
   1안은 색인 조회 한 번(수 ms)이고 토큰이 0 이다.

## 3. 만드는 법

### 표 두 개

```sql
sermons        id · preached_on(date) · title · preacher · video_url
               summary(text) · applications(text[])
               source_file_id · source_name · source_updated_at · ingested_at
sermon_refs    sermon_id · kind('main'|'quoted')
               book_code · chapter · verse_start · verse_end
```

`sermon_refs` 를 따로 두는 까닭은 **한 설교가 여러 구절에 걸리기** 때문이다.
머리글의 `본문` 은 `kind='main'`, 요약·적용 안에 나오는 성경 주소(로마서 10:14, 에스겔 3:18 …)는
`kind='quoted'` 로 함께 넣는다. 구절 파싱은 이미 있는 [lib/parseReference.ts](../lib/parseReference.ts) 를 쓴다.

**RLS 는 켜고 정책은 두지 않는다**(service_role 로만 읽는다) — 이 저장소의 기존 마이그레이션과 같은 꼴.

### 어느 설교를 보일지 — 점수

1. `main` 이 `quoted` 보다 앞선다
2. 고른 절이 설교 본문 **안에 들어가면**(포함) 걸치기만 한 것보다 앞선다
3. 같으면 **최근 설교**가 앞선다
4. **최대 두 편**만 보인다. 맞는 것이 없으면 카드를 그리지 않는다 — '관련 설교 없음' 을 쓰지 않는다
5. **위기 화면에서는 절대 그리지 않는다.** 그 자리에는 상담 창구만 있다(§B-1)

### 처음에는 드물게 보인다 (미리 말해 둘 것)

설교 50 편이면 `main` 구절이 50 개다. 성경은 1,189 장이니 아무 장이나 열어서 카드가 뜰 일은 거의 없다.
`quoted` 까지 넣으면 500 개쯤으로 늘어 **자주 읽는 본문(로마서·복음서·시편)에서는 꽤 뜬다.**
그래서 처음부터 `quoted` 를 함께 넣는 것이 맞다. 주마다 한 편씩 쌓이니 카드는 시간이 갈수록 자주 보인다.

### 설교를 들여오는 세 단계

| 단계 | 방법 | 새 의존 |
|---|---|---|
| **1** | 목사님이 .txt 를 내려 주시고 `scripts/ingest-sermons.ts` 를 사람이 한 번 돌린다 | 없다 |
| 2 | Drive API + 서비스 계정으로 그 폴더만 읽어 주 1회 자동 | **새 환경변수** — 프로덕션에서 실제로 되는지 확인해야 완료다 |
| 3 | 맞는 설교의 `-요약-` 을 프롬프트에도 붙인다 | 없다(교리 문서에 인용 규칙 추가) |

1단계 스크립트가 지켜야 할 것:
- 머리글 키의 **두 이름을 모두** 받는다(`제목`/`설교말씀`, `본문`/`설교본문`, `영상`/`영상링크`)
- `(preached_on, title)` 로 **덮어쓰기**(idempotent) — 같은 파일을 두 번 돌려도 늘어나지 않는다
- 파싱 못 한 파일·구절은 **화면에 목록으로 찍는다.** 조용히 넘기면 없는 설교가 된다
- 설교 **전문은 넣지 않는다**(1단계). 요약·적용만으로 카드가 된다

## 4. 재가에서 정해 주실 것

- [ ] 1단계로 갈 것인가 — **AI 는 설교를 보지 못하고, 앱이 카드로만 붙인다**
- [ ] 카드에 무엇을 보일까 — 제목 · 날짜 · 설교자 · 요약 첫 문단 · 영상 링크. **적용 질문도 보일까**
- [ ] 영상 링크를 누르면 유튜브로 나간다. 그대로 둘까
- [ ] 2025 년 7월 이전 설교가 다른 곳(`성경묵상_설교초` 등)에 있는가 — 있으면 함께 들여온다
- [ ] 설교자가 여럿일 때(청빙 강사 등) 카드에 이름을 그대로 쓸까
