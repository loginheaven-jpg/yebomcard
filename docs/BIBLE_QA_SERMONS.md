# 성경 질문 — 지난 설교를 어떻게 쓸 것인가 (설계안)

> 지휘부 질문(2026-09-18): "예봄교회 설교는 구글 드라이브에 텍스트로 저장되고 있다.
> 이것을 활용하여 질문에 대해 이전 설교 내용을 인용하거나 소개할 방법이 있을까?"
> 3개 안을 세 관점(교리 안전 · 구현 실효 · 목회 유용)으로 검증한 결과다.
> **상태: 만들었다(2026-09-18). 남은 것은 드라이브 폴더 공유 하나뿐이다.**
> 1단계대로 **AI 에게 설교를 주지 않고** 앱이 카드로 따로 붙인다.
> 코드: `lib/sermons/{parse,ingest}.ts` · `app/api/cron/ingest-sermons` · `app/api/bible-qa/sermons` ·
> `vercel.json`(매일 20:00 UTC = 한국 05:00) · `npm run verify:sermon` · `npm run ingest:sermons`
> 카드에 **적용 질문은 넣지 않는다.** 들여오기는 **자동으로 매주** 돈다(아래 §4).

## 1. 드라이브에 실제로 무엇이 있는가 (2026-09-18 확인)

한 폴더(`1l2K2CMjvqKl6k7dTfgXM--E_L1dqavlm`)에 `YYYY년 M월 D일 주일설교.txt` 로
**50 편**이 있다(2025-07-27 ~ 2026-09-06, 빠진 주가 더러 있다). 파일 하나가 2~11 KB.
설교자가 다르면 제목에 이름이 붙는다(`… 주일설교 최병희 목사님`, `… 정용재 목사님`).

**머리글이 정해진 꼴로 들어 있다** — 이것이 이 설계의 열쇠다. 본문 구절을 사람이 이미 적어 두었으니
기계가 추측할 일이 없다.

```
날짜 : 2026년 9월 6일 주일설교
제목 : 빈 배의 축복
설교자 : 최병희 목사님
본문 : 누가복음 5:1-11
영상링크 : https://youtu.be/...

-요약-   (이미 잘 다듬어진 3~4 문단)
-적용-   (1. 2. 3. 목장에서 나눌 질문)
```

**주의 — 키 이름이 해마다 바뀌었다.** 2025 년 파일은 `설교말씀` · `설교본문` · `영상`,
2026 년 파일은 `제목` · `본문` · `영상링크` 다. 읽는 코드는 **두 이름을 모두 받아야** 하고,
못 읽은 파일은 조용히 버리지 않고 목록으로 보고해야 한다.

곁가지로 얻은 것: 설교 본문에 **VIP**(전도 대상)가 실제로 쓰인다 →
[BIBLE_QA_HOUSECHURCH.md](BIBLE_QA_HOUSECHURCH.md) 의 낱말 목록에 `VIP` 를 넣는 것이 맞다.

## 2. 세 가지 안과 판정

| | 안 | 하는 일 | 판정 |
|---|---|---|---|
| **1** | **앱이 카드로 붙인다** | 구절 → 설교 색인을 앱이 찾아, AI 답 **옆에** '이 구절을 다룬 우리 교회 설교' 카드를 그린다. AI 는 설교를 보지 못한다 | **채택(1단계)** |
| 2 | 요약을 프롬프트에 넣는다 | 맞는 설교의 `-요약-` 을 인용 블록으로 붙이고 "여기 있는 말만 우리 교회 설교로 인용하라" 고 묶는다 | 3단계에. 카드와 **함께**만 |
| 3 | 설교 전문을 검색해 넣는다(RAG) | 임베딩으로 본문을 쪼개 검색해 넣는다 | **하지 않는다** |

**1안을 택한 이유 셋.**

1. **목사님 입에 없던 말이 들어가지 않는다.** 3안·2안은 모델이 요약을 다시 요약하면서
   어투와 강조를 바꾼다. 교인은 그것을 "우리 목사님이 그러셨다" 로 읽는다.
   카드는 **제목 · 날짜 · 요약 첫 문단 · 영상 링크**를 그대로 보여 주고, 판단은 교인이 한다.
2. **답의 틀을 지킨다.** 답은 네 줄 9~14 문장에 구절 3 개까지다([BIBLE_QA_DOCTRINE.md](BIBLE_QA_DOCTRINE.md) §4).
   3천 자 설교를 밀어 넣으면 이 틀이 무너진다.
3. **돈도 시간도 들지 않는다.** 게이트웨이에 임베딩 창구가 없어 3안은 새 외부 의존이 생긴다.
   1안은 색인 조회 한 번(수 ms)이고 토큰이 0 이다.

## 3. 만드는 법

### 표 두 개

```sql
sermons        id · preached_on(date) · title · preacher · video_url
               summary(text) · applications(text[])
               source_file_id · source_name · source_updated_at · ingested_at
sermon_refs    sermon_id · kind('main'|'quoted')
               book_code · chapter · verse_start · verse_end
sermon_ingest_runs
               id · ran_at · trigger('cron'|'manual') · scanned · inserted · updated
               failures(jsonb)   -- 파일 이름과 못 읽은 까닭. 관리자 화면에서 본다
```

`sermon_refs` 를 따로 두는 까닭은 **한 설교가 여러 구절에 걸리기** 때문이다.
머리글의 `본문` 은 `kind='main'`, 요약·적용 안에 나오는 성경 주소(로마서 10:14, 에스겔 3:18 …)는
`kind='quoted'` 로 함께 넣는다. 구절 파싱은 이미 있는 [lib/parseReference.ts](../lib/parseReference.ts) 를 쓴다.

**RLS 는 켜고 정책은 두지 않는다**(service_role 로만 읽는다) — 이 저장소의 기존 마이그레이션과 같은 꼴.

### 어느 설교를 보일지 — 점수

1. `main` 이 `quoted` 보다 앞선다
2. 고른 절이 설교 본문 **안에 들어가면**(포함) 걸치기만 한 것보다 앞선다
3. 같으면 **최근 설교**가 앞선다
4. **최대 두 편**만 보인다. 맞는 것이 없으면 카드를 그리지 않는다 — '관련 설교 없음' 을 쓰지 않는다
5. **위기 화면에서는 절대 그리지 않는다.** 그 자리에는 상담 창구만 있다(§B-1)

### 처음에는 드물게 보인다 (미리 말해 둘 것)

설교 50 편이면 `main` 구절이 50 개다. 성경은 1,189 장이니 아무 장이나 열어서 카드가 뜰 일은 거의 없다.
`quoted` 까지 넣으면 500 개쯤으로 늘어 **자주 읽는 본문(로마서·복음서·시편)에서는 꽤 뜬다.**
그래서 처음부터 `quoted` 를 함께 넣는 것이 맞다. 주마다 한 편씩 쌓이니 카드는 시간이 갈수록 자주 보인다.

### 카드에 보이는 것 (지휘부 2026-09-18)

제목 · 날짜 · 설교자 · 요약 첫 문단 · 영상 링크. **적용 질문은 보이지 않는다.**
적용은 목장에서 나눌 질문이라 혼자 읽는 자리에 놓을 것이 아니고, 답의 마지막 줄
'목회자와 나눠 볼 질문' 과도 겹친다. 다만 **표에는 담아 둔다**(`applications`) — 공짜이고,
3단계에서 쓸 수 있으며, 나중에 보이기로 정해도 다시 들여올 일이 없다.

## 4. 들여오기 — 사람 손 없이 매주 (지휘부 요구)

설교는 주마다 새로 나온다. **사람이 기억해서 돌리는 일은 결국 멈춘다** —
자동으로 돌지 않으면 카드는 몇 주 만에 옛것이 된다.

### 언제 도는가 — 주 1회가 아니라 **하루 1회**

드라이브 파일의 올라온 시각을 세어 보니 **월·화·수로 흩어져 있다**
(2026 년: 8/3 월 · 8/19 수 · 7/6 월 · 7/1 수 · 6/22 월 · 6/15 월 · 5/6 수 · 9/8 화 …).
주 1회로 정해 두면 그 요일보다 늦게 올라온 주의 설교는 **꼬박 한 주를 기다린다.**
그래서 **하루 한 번** 돌린다 — 드라이브 목록 조회 한 번(수 ms, 공짜)이고,
설교가 올라온 **다음 날 아침에 카드가 생긴다.** 결과는 지휘부가 말씀하신 '매주 자동 갱신' 이고,
늦어지는 일이 없다.

- `vercel.json` 에 `crons` 로 `/api/cron/ingest-sermons` 를 매일 20:00 UTC(= 한국 05:00)
- **바뀐 파일만** 들여온다 — 드라이브의 `modifiedTime` 이 표의 `source_updated_at` 보다 새로울 때만.
  목사님이 지난 설교 글을 고치셔도 다음 날 반영된다
- 아무도 아무 때나 부르지 못하게 `CRON_SECRET` 으로 막는다(Vercel 이 `Authorization: Bearer` 로 보낸다).
  수퍼어드민 세션으로도 손으로 한 번 돌릴 수 있게 둔다 — 급할 때 기다리지 않도록

### 열쇠는 이미 있다 — **새 비밀값이 없다**

드라이브를 읽으려면 구글 인증이 필요한데, [app/api/tts/route.ts](../app/api/tts/route.ts) 가
이미 `GCP_SERVICE_ACCOUNT_JSON` 으로 RS256 JWT 를 만들어 액세스 토큰을 받고 있다.
**scope 만 `drive.readonly` 로 바꾸면 그대로 쓴다** — 새 패키지도, 새 환경변수도 없다
(`CRON_SECRET` 하나만 새로 넣는다). 그 서명 코드를 `lib/google/accessToken.ts` 로 꺼내
TTS 와 설교가 함께 쓴다.

**사람이 드라이브에서 해 주셔야 하는 일이 하나 있다** — 서비스 계정 메일 주소에
폴더를 **보기 권한으로 공유**해야 한다. 서비스 계정은 공유받지 않은 파일을 보지 못한다.

**폴더는 지금 것을 그대로 쓴다(지휘부 2026-09-18).** 설교만 담긴 폴더를 따로 만들자고 했으나,
지휘부가 "다른 정보를 참고해도 괜찮다. 현재 폴더를 이용하라" 고 정했다. 그 폴더에는 교인명부·재정·
당회록도 함께 있어 **앱의 열쇠가 그것까지 읽을 수 있는 상태가 된다** — 알고 택한 것이다.
대신 코드에서 다음 세 가지로 좁힌다:

- 들여올 파일은 **`text/plain` 이고 이름에 `주일설교` 가 든 것만**. 다른 파일은 목록에서 걸러 낸다
- **내용을 내려받는 것도 그 파일들만.** 폴더의 다른 파일은 이름조차 표에 남기지 않는다
- 이 좁히기는 **코드의 약속이지 권한의 담이 아니다.** 뒤에 교인명부 같은 것이 더 민감해지면
  그때 하위 폴더로 옮겨 공유를 좁히는 것이 옳다 — 그때 코드는 고칠 데가 없다(폴더 id 한 줄)

### 들여오는 코드는 한 벌 (`lib/sermons/ingest.ts`)

처음 50 편(과거분)과 매일 한 편(새것)은 **같은 일**이다. 파서와 저장을 한 모듈에 두고
들어오는 문만 둘로 한다 — 손으로 한 번 돌리는 `scripts/ingest-sermons.ts` 와
매일 도는 `/api/cron/ingest-sermons`.

지켜야 할 것:
- 머리글 키의 **두 이름을 모두** 받는다(`제목`/`설교말씀`, `본문`/`설교본문`, `영상`/`영상링크`)
- `(preached_on, title)` 로 **덮어쓰기**(idempotent) — 같은 파일을 두 번 읽어도 늘어나지 않는다
- 파싱 못 한 파일·구절은 **버리지 않고 남긴다**(`sermon_ingest_runs`), 관리자 화면에서 본다.
  조용히 넘기면 없는 설교가 되고, 아무도 모른다
- 설교 **전문은 넣지 않는다**(1단계). 요약·적용만으로 카드가 된다

### 그 다음 (3단계)

맞는 설교의 `-요약-` 을 프롬프트에 인용 블록으로 붙인다. 새 의존은 없고,
교리 문서에 "요약에 있는 말만 우리 교회 설교로 인용한다" 는 규칙을 더한다.
이때도 **카드는 함께 보인다** — 교인이 직접 확인할 수 있어야 한다.

## 4-2. 만든 것과 확인한 것 (2026-09-18)

| 무엇 | 어디 |
|---|---|
| 머리글·요약·적용·인용구절 파서 | `lib/sermons/parse.ts` |
| 드라이브 목록·내려받기·저장 | `lib/sermons/ingest.ts` (입구 둘: cron · 손) |
| 매일 한 번 | `app/api/cron/ingest-sermons` + `vercel.json` (`0 20 * * *`) |
| 카드 조회 | `app/api/bible-qa/sermons` — **답변과 다른 라우트**. `Cache-Control: max-age=3600` |
| 화면 카드 | `components/BibleQaSheet.tsx` — 답 **아래**, 위기·거절에는 그리지 않는다 |
| 파서 시험 26항목 | `npm run verify:sermon` |

**폴더는 `SERMON_DRIVE_FOLDER_ID` 로 덮어쓸 수 있고, 기본값은 지금 쓰는 폴더다.**
폴더 id 는 비밀값이 아니다 — 서비스 계정에 **보기 권한으로 공유**해야 열린다.
공유되지 않았으면 목록이 **0편**으로 나오고 오류는 나지 않는다(그때는 공유가 먼저다).

**파서가 두 꼴을 다 읽는지 실제 파일로 확인했다.** 2025 년(`설교말씀`·`설교본문`·`영상`)과
2026 년(`제목`·`본문`·`영상링크`) 모두 통과하고, `로마서 10장 14절` · `마태복음 28장 18절로 20절`
같은 한글 꼴 인용도 색인된다. 못 읽은 파일은 `sermon_ingest_runs.failures` 에 까닭과 함께 남는다.

**카드가 위기 화면에 뜨지 않는 것도 화면으로 확인했다.** 카드 조회는 질문과 **같은 순간**에
따로 나가므로(그래야 답변 시간에 더해지지 않는다) 위기·거절로 판정되면 그 결과를 버린다.

## 5. 정해진 것과 남은 것

**정해졌다 (지휘부 2026-09-18)**
- [x] **1단계로 간다** — AI 는 설교를 보지 못하고, 앱이 카드로만 붙인다. 2·3단계는 그 다음에
- [x] **적용 질문은 카드에 넣지 않는다**(표에는 담아 둔다)
- [x] **2025 년 7월 이전 설교는 유튜브에만 있다** — 글이 없으니 넣지 않는다. 뒤에 글이 생기면 그때 더한다
- [x] **매주 자동으로 갱신된다** — 하루 한 번 도는 것으로 그 요구를 넘겨 채운다(§4)

**남은 것 — 사람이 해야 하는 두 가지. 둘 다 안 하면 자동 들여오기가 조용히 안 돈다**
- [ ] **드라이브 폴더를 서비스 계정 메일에 보기 권한으로 공유.** 안 하면 목록이 **0편**으로 나오고
      **오류는 나지 않는다** — `/api/bible-qa/health` 의 `cron.last_run.scanned` 가 0 이면 이것이다
- [ ] **Vercel 에 `CRON_SECRET` 환경변수 추가.** 없으면 Vercel cron 이 인증 헤더 없이 와서
      라우트가 403 으로 막는다 — 날마다 부르지만 **한 번도 들어오지 못하고**, 이것도 오류가 안 난다.
      `/api/bible-qa/health` 의 `cron.secret_set` 이 false 면 이 상태다
      (그 동안에도 수퍼어드민이 `/api/cron/ingest-sermons` 를 손으로 열면 들어온다)
