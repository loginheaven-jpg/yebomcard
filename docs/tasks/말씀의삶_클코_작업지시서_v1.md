## 0. 한 줄 요약

예봄성경에 하단 6번째 탭 **말씀의삶**을 추가한다. 예봄교회 '성경읽기진도표' 91회차 순서로 함께 읽는 성경북클럽 기능이다. **성경 본문·역본 비교·TTS·글꼴은 한 줄도 바꾸지 않는다.** 91회차 순서는 본문 위에 얹는 얇은 '플랜' 층이며, 기존 `reading_progress`(장 단위 자동 기록)에서 회차 완료를 **파생 계산**한다.

## 1. 확정 사양 (지휘부 결정 — 재논의 불가)

| 항목 | 결정 |
|---|---|
| 진입 | 하단 탭 추가(교체 아님). 순서 목차 / 검색 / 본문 / **말씀의삶** / 책갈피 / 설정 |
| 탭 라벨 | `말씀의삶` (띄어쓰기 없음), 아이콘 체크서클 계열 |
| 플랜 정의 | 정적 파일 `lib/plans/yebom91.ts` (DB 아님). 플랜 id `yebom91` |
| 회차 일정 | 없음. 순서만 |
| 완료 판정 | **자동 + 수동 병행**. 자동 = 회차 구간의 모든 장이 `reading_progress`에 존재. 수동 = `reading_unit_checks` 행 존재. 둘 중 하나면 완료 |
| '지금' 회차 | **가장 낮은 미완료 seq** (= 연속 완료 구간 다음). 순서 밖에서 완료한 회차가 있어도 앞의 미완료가 우선 |
| 순서 밖 읽기 | 판정은 장 집합 기준이라 순서 무관. 일부만 읽은 회차는 '진행중'으로 표시 |
| 절 경계 회차 (39↔40 등) | 장 단위로 판정. 경계 장은 양쪽 회차 모두에 속하고, 읽으면 둘 다 채움. 헤더에만 `15:22까지` 표기 |
| 수동 체크 진입 | 진도표 행 **길게 누름**(500ms) → "종이로 읽음" 체크/해제. 체크박스 직접 탭 아님 |
| 회차 완료 시트 | 회차 마지막 장 3초 열람 → 자동 판정 완료 → 바텀시트 1회. 1차 버튼 "다음 회차 첫 장 읽기", 2차 "진도표 보기" |
| 플랜 모드 이동 | 플랜 모드에서 이전/다음(버튼·스와이프)이 **플랜 순서**를 따름. 열왕기상 11장 → 아가 1장 |
| 플랜 헤더 | 본문 위 카드. 플랜 모드일 때만. 목차·검색 탭 진입 시 플랜 모드 해제 |
| 그룹 | 다중 그룹. 초대코드 6자리(영대문자+숫자, 혼동 문자 0/O/1/I 제외). 생성자 = 관리자 |
| 그룹 화면 | 완료 회차 수 내림차순 막대, 이름·순위·회차 전부 공개. 내 행 강조. 동률은 먼저 마친 사람이 위 |
| 진도 소유 | 개인 1개. 여러 그룹에 속해도 같은 진도. 그룹은 "누구 진도를 같이 볼 것인가"만 결정 |
| 첫 그룹 | `말씀의삶1기` — 배포 후 최박사가 UI로 생성. seed SQL 없음 |
| 비로그인 | 진도표는 열람 가능, 체크·진행 표시·그룹은 로그인 유도(`saint.yebom.org/login?from=bible`) |
| 디자인 | 기존 토큰(`--paper/--ink/--amber*`) 그대로. 시안 HTML `말씀의삶_주요화면시안.html` 참조(별첨) |

### 3.2 타입·유틸 (시그니처 고정)

```ts
export interface PlanRange {
  book: string;      // lib/books.ts code
  fromCh: number;
  toCh: number;
  fromVs?: number;   // 절 경계 표기용. 판정에는 쓰지 않는다
  toVs?: number;
}
export interface PlanUnit { seq: number; label: string; ranges: PlanRange[] }
export interface ReadingPlan { id: "yebom91"; name: string; units: PlanUnit[] }

/** 회차의 장 목록. 같은 회차 안 중복 장(예: 10회차 민수기 9)은 1회만, 등장 순서 유지 */
export function unitChapters(unit: PlanUnit): { book: string; chapter: number }[];

/** 플랜 전체를 읽기 순서대로 펼친 배열. 경계 장은 회차마다 다시 등장한다(양쪽 소속) */
export interface PlanChapter { seq: number; book: string; chapter: number; idx: number }
export function flattenPlan(plan: ReadingPlan): PlanChapter[];

/** 현재 위치의 플랜 인덱스. (seq, book, chapter) 로 찾는다 — 경계 장은 seq 로 구분 */
export function findPlanIndex(flat: PlanChapter[], seq: number, book: string, chapter: number): number;

export type UnitStatus = "done" | "partial" | "todo";
export interface UnitProgress { seq: number; status: UnitStatus; readCount: number; total: number; manual: boolean }
export interface PlanProgress {
  units: UnitProgress[];
  doneCount: number;           // 완료 회차 수
  currentSeq: number;          // 가장 낮은 미완료 seq. 전부 완료면 91
  nextChapter: { seq: number; book: string; chapter: number } | null; // currentSeq 안에서 안 읽은 첫 장
}
export function computeUnitProgress(
  plan: ReadingPlan,
  readByBook: Record<string, Set<number>>,   // lib/reading-progress computeProgress().readByBook 그대로
  manualSeqs: Set<number>,
): PlanProgress;
```

판정 규칙:
- `total` = `unitChapters(unit).length`, `readCount` = 그중 `readByBook[book]`에 있는 장 수
- `done` = `manual` 이거나 `readCount === total`
- `partial` = `!done && readCount > 0`
- `currentSeq` = status !== "done" 인 최소 seq. 없으면 91
- `nextChapter` = currentSeq 회차의 `unitChapters` 중 첫 미읽 장. 수동 완료 회차는 건너뜀

## 6. 단계 4 — 그룹

### 6.1 DB

```sql
create table if not exists public.reading_groups (
  id          bigint generated by default as identity primary key,
  name        text        not null,
  invite_code varchar(6)  not null unique,
  plan_id     varchar(20) not null default 'yebom91',
  created_by  text        not null,
  created_at  timestamptz not null default now()
);
create table if not exists public.reading_group_members (
  group_id   bigint      not null references public.reading_groups(id) on delete cascade,
  user_id    text        not null,
  user_name  text,
  joined_at  timestamptz not null default now(),
  primary key (group_id, user_id)
);
create index if not exists reading_group_members_user_idx on public.reading_group_members (user_id);
alter table public.reading_groups enable row level security;
alter table public.reading_group_members enable row level security;
```
`user_name`은 세션 `name` 저장(`verse_notes` 패턴). 표시 이름 변경은 재참여 시 갱신.

### 6.2 API `app/api/reading-groups/`

| 경로 | 메서드 | 동작 |
|---|---|---|
| `route.ts` | GET | 내 그룹 목록 + 각 그룹 멤버 수 |
| `route.ts` | POST `{name}` | 생성 + 생성자 자동 참여. 초대코드 서버 생성(충돌 시 재생성 3회) |
| `join/route.ts` | POST `{code}` | 코드로 참여. 대소문자 무시. 없는 코드 404 |
| `[id]/standings/route.ts` | GET | 멤버별 `{user_id, user_name, doneCount, lastDoneAt}` 내림차순. 멤버만 조회 가능 |
| `[id]/leave/route.ts` | POST | 탈퇴. 생성자는 마지막 멤버일 때만 탈퇴 = 그룹 삭제 |

standings 계산: 멤버 전원의 `reading_progress` + `reading_unit_checks`를 한 번에 가져와 서버에서 `computeUnitProgress`(lib는 Node에서도 동작). `lastDoneAt` = 완료 회차 중 마지막 완료 시각(자동은 회차 마지막 장 `read_at`, 수동은 `checked_at`). 동률 정렬 키. 30명 이하 그룹 기준으로 N+1 없이 IN 쿼리 2회.
