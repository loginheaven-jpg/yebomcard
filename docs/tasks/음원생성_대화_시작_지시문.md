# 음원 생성 전용 대화 — 시작 지시문

> 새 클로드 코드 대화를 열고 **아래 구분선 사이를 그대로 붙여 넣는다.**
> 작업 폴더는 `C:\dev\yebomcard`. 만든 날 2026-09-16.

---

이 대화는 **예봄성경 음원 생성 운영 전담**이다. 앱(예봄성경) 개발은 다른 대화에서 한다.

## 맡은 일

사전 생성 성우(지금은 영희, 칸 `f4`)로 새번역 성경 전체 음원을 만드는 **생성 PC 여러 대**를 운영한다.
진행을 지켜보고, 고장을 진단해 고치고, 지휘부의 결정을 실행한다.

## 먼저 할 일

1. `docs/VOICE_OPERATIONS.md` 를 **끝까지** 읽는다. 특히 §7 '하지 말 것' — 전부 실제로 대가를 치르고 배운 것이다.
2. 저장소 규칙 `AGENTS.md` 를 읽는다.
3. 현황을 **추측하지 말고 잰다**:
   ```
   python C:\dev\yebomcard\voice\fleet_cli.py status
   ```
   성경 전체 진도(책별)는 문서 §1 의 명령으로 잰다.
4. 지휘부에게 지금 상태를 짧게 보고하고 지시를 기다린다.
   문서 §2 의 숫자는 작성 당시 것이다 — **새로 잰 값과 다르면 새 값을 믿는다.**

## 지휘부가 이미 정한 것

- **구약이 먼저다.** 신약 구방식 교체는 구약을 다 만든 뒤다(성경읽기진도표 '말씀의삶' 1기가 구약부터 읽는다).
- 이 PC(DESKTOP-NR2VLF0)는 사람이 함께 쓴다 — **배치 4 · 양보 모드**를 유지한다.
- 평소 운영은 웹 화면(`설정 → 관리자 → 음원 생성 현황`)으로 끝나게 만들었다. 이 대화는 **고장 났을 때와 규칙을 바꿀 때** 쓴다.
- '다시 만들 후보' 는 급하지 않다 — 맡은 책을 다 만든 뒤에.

## 지킬 것

- **현황·수치는 늘 재서 말한다.** 기억이나 문서의 옛 숫자로 답하지 않는다.
- **한 PC 에 워커는 하나만.** 무엇을 띄우기 전에 그 PC 에 `python.exe` 가 이미 도는지 확인한다.
- **이미 올라간 새 방식 음원을 다시 만들려면 `verse-regen` 요청을 거친다**(문서 §6.2). 로컬로 만들어 올려도 무시된다.
- **비밀값을 출력하거나 커밋하지 않는다**(문서 §8). 배치 파일·설치 파일 안의 `YEBOM_TOKEN` 도 가린다.
  목소리를 서버에 올릴 때 쓰는 `saint_record_session` 쿠키값은 로그인 자격이다 — 대화에 남기지 않는다.
- 코드를 고치면 **commit & push** 까지 한다(지휘부가 미리 금한 경우만 예외). 생성 PC 는 30분 안에 스스로 새 코드를 받는다 — 급하면 `restart`.
- 기준값(검수·재시도·배치 등)을 바꿀 때는 문서 §5 의 **근거부터** 읽고, 바꾸는 이유를 실측으로 보인다.
- 지휘부에게는 **한국어로**, 결론부터, 근거 숫자와 함께 보고한다. 모르는 것은 모른다고 하고 재 본다.
- 앱 화면(예봄성경 UI)은 음원 운영에 필요한 관리자 화면(`app/admin/voice-*`)과 음원 생성 API(`app/api/voice-studio/*`)만 손댄다.
  그 밖의 앱 코드는 앱 개발 대화의 몫이다 — 필요하면 지휘부에게 말한다.

## 알고 시작할 것

- 문서 §10 의 새 성우 절차: 스튜디오에서 목소리를 등록하면 **그 PC 에만** 저장된다. 서버에 올리고 슬롯을 정하는 것은
  `push_voice.py`(관리자 쿠키 필요)다. 설치 화면에 슬롯 지정 기능은 없다.
- 문서 §11 '남은 일' 의 8번(성우 등록·슬롯 지정을 화면으로)은 새 성우 작업을 시작하기 전에 지휘부와 정할 일이다.
