## 1. 한눈에 보는 체계

```
 ┌──────────── 생성 PC (여러 대) ────────────┐
 │  스튜디오 app.py (Gradio, :7860)          │
 │   ├ 워커 jobs.py   작업 큐 → 생성 → 검수 → 업로드
 │   └ fleet.py       10초마다 현황 보고 · 지시 수신 · 자동 회복 · 코드 갱신
 └──────────────┬────────────────────────────┘
                │ 기기 토큰(studio.json)
 ┌──────────────▼────────────────────────────┐
 │  예봄성경 서버 (Vercel)  /api/voice-studio/* │
 │   현황·지시·임대·진도는 R2 에 JSON 으로 둔다   │
 │   음원은 R2 공유 캐시 tts/v1/ko/{성우}/{sha1}.mp3
 └──────┬──────────────────────────┬─────────┘
        │ 관리자 세션                │ 기기 토큰
 ┌──────▼─────────────┐   ┌────────▼───────────────┐
 │ 웹 화면(지휘부)      │   │ fleet_cli.py(이 대화)    │
 │ 설정→관리자→         │   │ status · books · log    │
 │  음원 생성 현황      │   │ stop · resume · restart │
 │  음원 보류 절 검수   │   │ queue · replace · regen │
 │  음원 생성 PC 설치   │   │ batch · polite          │
 └────────────────────┘   └────────────────────────┘
```

**생성 PC 는 집·사무실 안에 있어 서버가 먼저 연결할 수 없다.** 그래서 모든 지시는 서버에 걸어 두고
PC 가 가져가는 방식이다 — **지시는 즉시 반영되지 않고 10초 안에** 반영된다.

### 명령줄 도구 (이 대화의 손)

```bash
cd C:\dev\yebomcard\voice
python fleet_cli.py status              # 전체 현황 (--json 으로 기계가 읽을 형태)
python fleet_cli.py books               # 임대 배분 현황
python fleet_cli.py log                 # 최근 지시와 결과

python fleet_cli.py stop    [--pc 이름]           # 생성 멈춤
python fleet_cli.py resume  [--pc 이름]           # 생성 이어가기
python fleet_cli.py restart [--pc 이름]           # 스튜디오 다시 시작
python fleet_cli.py batch 4 --this-pc --pc 이름   # 그 PC 가 앞으로 집는 작업까지 배치 4
python fleet_cli.py polite on --pc 이름           # 양보 모드
python fleet_cli.py queue 창세기,출애굽기 --pc 이름 [--voice 영희]
python fleet_cli.py replace 신약 --pc 이름         # 구방식 교체 작업 걸기
python fleet_cli.py regen "창세기 1:1,창세기 1:2"
```

`--pc` 는 이름 일부만 써도 된다. 생략하면 **모든 PC**.

`status` 맨 위의 '성경 전체 · 남은 절 · 이 속도면' 은 **서버 실측**(진도 API, 1분 돌려 쓰는 값)이다.
PC 줄의 '작업 파일의 남은 절' 은 그 PC 작업 파일의 숫자라 다른 PC 가 만든 절이 늦게 빠진다 — 전체 판단에 쓰지 않는다.

책별 진도는 명령줄 도구에 없다 — 서버 API 로 잰다(몇 초 걸린다, 생성 PC 에는 부담 없음):

```bash
python -c "import sys,requests; sys.stdout.reconfigure(encoding='utf-8'); sys.path.insert(0,'.'); import server; d=requests.get(server.config()['base']+'/api/voice-studio/progress?fresh=1', headers=server._headers(), timeout=300).json(); print(d['done'], '/', d['total'], '· 구방식', d['legacy'])"
```

**원칙: 평소 운영은 웹 화면으로 끝나게 만들었다.** 이 대화는 **고장 났을 때와 규칙을 바꿀 때** 쓴다.

### 웹 화면 버튼의 뜻 (자주 헷갈리는 것)

- `생성 멈춤` / `생성 이어가기` — 만들기만 멈추고 다시 시작한다. 프로그램은 그대로다.
- `스튜디오 다시 시작` — 프로그램을 껐다 켠다. **평소에는 누를 일이 없다**(코드 갱신·그래픽 오류 회복이 자동이다).
- `N절씩` — 이 PC 가 **앞으로 집는 작업까지** 적용된다(지금 작업만이 아니다).

## 4. 상황별 대응 (런북)

### 4.1 '손봐야 할 것' 배지가 떴다
현황 화면 맨 위에 무엇인지 줄마다 뜬다. 세는 것은 넷뿐이다(실제로 손해가 난 것만 골랐다 — 늘 켜져 있으면 아무도 안 본다):

| 표시 | 뜻 | 조치 |
|---|---|---|
| 🔴 응답 없는 PC | 10분 넘게 보고 없음 | 그 PC 에서 바탕화면 실행 파일을 다시 누른다. 창이 닫혀 있거나 PC 가 꺼졌을 것 |
| 🟠 오류로 멈춘 작업 | 자동 회복이 3번 해 보고 손을 뗌 | 메시지를 보고 진단(§4.4). 화면의 `다시 켜기` 로 한 번 더 시도 |
| 🟡 노는 PC | 할 일이 없음 | `책 맡기기` |
| 🟡 보류 절 10개 이상 | 사람 판단이 밀림 | `음원 보류 절 검수` |

### 4.2 '스튜디오 코드가 다릅니다' 경고
**30분 기다린다.** 각 PC 는 30분마다 디스크의 소스 지문을 돌고 있는 것과 비교해 다르면 스스로 다시 켠다
(설치본은 먼저 서버에서 받아 온다). 30분이 지나도 남아 있으면 그때가 문제다 — `restart --pc` 로 밀어 넣는다.
급한 수정을 push 했다면 기다리지 말고 곧바로 `restart` 한다.

### 4.3 한 PC 의 속도가 뚝 떨어졌다 / GPU 는 100% 인데 절이 안 나온다
**그래픽 메모리가 넘친 것이다.** 윈도우 드라이버는 이때 **예외를 내지 않고** 시스템 메모리로 흘려보낸다 —
오류 없이 기어가기만 한다(실제 사고: 3060 이 배치 8 로 **39분간 0절**, VRAM 98%).
절당 180초를 넘으면 워커가 알아서 배치를 반으로 줄이지만(`STALL_SEC_PER_VERSE`), 그래도 느리면
`batch 4 --this-pc` 로 고정한다.

**먼저 기계 상태를 본다**(웹 PC 카드 아래 · `fleet_cli.py status` 의 PC 줄, 2분마다 갱신):
- `넘침 N GB` — 스튜디오가 잡은 그래픽 메모리 중 **시스템 메모리로 흘러간 양**. 0.5GB 넘으면 붉게 뜬다 → 배치를 줄인다
- `다른 프로그램: …` — 그래픽 메모리를 먹는 다른 프로그램(게임·브라우저 등). 사람이 쓰는 PC 면 흔하다
- `과열` · `제한: 전력 제한` — 클럭이 깎이는 이유
- `CPU 많이 쓰는 것: 스튜디오 1.0코어` — 생성은 코어 하나에 묶인다. 스튜디오가 1코어에 못 미치고 다른 것이 바쁘면 CPU 다툼 → 양보 모드·사람의 사용이 원인(배치로는 안 풀린다, §7)

### 4.4 작업이 오류로 멈췄다
- **`CUDA error: unknown error`** — 그래픽 드라이버가 응답을 잃었다(드라이버 업데이트·재부팅 중 흔함).
  같은 프로세스에서는 되살릴 수 없어 워커가 **스튜디오를 스스로 다시 켠다**. 켠 지 10분 안에는 다시 켜지 않는다.
- **`CUDA out of memory`** — 배치를 반으로 → 배치 1 → 검수 모델(Whisper)을 CPU 로 내림 → 그래도 안 되면
  "이 PC 로는 할 수 없습니다". **다시 켜기로는 안 풀린다**(VRAM 이 늘지 않는다) — 자동 회복도 이것은 다시 켜지 않는다.
- **`DLL load failed ... 애플리케이션 제어 정책에서 이 파일을 차단했습니다`** — 윈도우 11 **스마트 앱 제어**.
  `설정 → 개인 정보 및 보안 → Windows 보안 → 앱 및 브라우저 제어 → 스마트 앱 제어 → 끄기`.
  ⚠ **한 번 끄면 다시 켤 수 없다**(윈도우 재설치 필요) — 지휘부에게 알리고 결정받는다.

### 4.5 새 PC 를 붙인다
1. 지휘부가 `설정 → 관리자 → 음원 생성 PC 설치` 에서 **설치 파일을 새로 받는다**(토큰이 파일에 박혀 있다 — 옛 파일은 옛 설치 절차다).
2. 그 PC 에서 더블클릭. 파이썬이 없으면 winget 으로 설치하고, GPU 확인 → 패키지(6GB, 10~40분) → 소스 → 목소리 순.
3. 처음 켜면 **모델 3.86GB 를 내려받는다**. `hf_xet` 설치 안내가 떠도 무시한다.
4. 현황에 뜨면 GPU 를 보고 배치를 정한다 — **12GB 미만이면 `batch 4 --this-pc`**.
5. 겹치지 않게 책을 맡긴다(§2 표 갱신).

VRAM 별 기대치:

| VRAM | 결과 |
|---|---|
| 12GB | 배치 8 (3060 은 빠듯해 4 권장) |
| 10~11GB | 자동으로 4 |
| 8GB | 배치 2~4, 느려짐 |
| 6~7GB | 배치 1 + 검수 CPU, 겨우 돈다 |
| 6GB 미만 | **설치 때 막는다** — 모델만 4.6GB |

### 4.6 배치 파일을 눌렀는데 창이 한동안 비어 있다
정상이다. 첫 줄 `[시작] … 켜는 중입니다` 가 바로 찍히고, 끝난 작업들의 본문 맞추기가 **뒤에서** 1분 남짓 돈다
(작업이 쌓일수록 길어진다 — 56개에 76초). 그동안에도 생성은 이미 돈다.

### 4.7 창이 저절로 닫혔다
스튜디오가 스스로 다시 켠 것이다(코드 갱신 또는 그래픽 오류 회복). **새 창이 따로 열려 있다.**

### 5.1 생성·검수 (`voice/engine.py`, `voice/jobs.py`)

| 이름 | 값 | 뜻과 근거 |
|---|---|---|
| `METHOD` | `ns1` | 새 방식(본문 통째로 넣기). 옛 방식(흘려 넣기)은 절 끝이 잘렸다 |

| `GAP_MAX` | 8 | 한 자리에서 연속 8자 이상 빠졌으면 불합격 — **일치율보다 먼저 본다** |
| `CPS_TRUST_MAX` | 9.0 | 자/초가 이 안이고 빠진 자리도 없으면 **일치율이 낮아도 통과**(이름 오인식) |
| `DEFAULT_BATCH` | 8 | 모자라면 워커가 줄인다 |
| `STALL_SEC_PER_VERSE` | 180 | 절당 이보다 오래 걸리면 기어가는 것 → 배치 반으로 |
| `ASR_MODEL` | `small` | 검수용 Whisper |

**끝음절 잘림은 '뽑기' 다.** 같은 본문을 두 번 넣어도 230ms 와 40ms 가 나온다. 온도·끝 공백·줄바꿈·강제 조각·
문장부호 끄기 — **어떤 조건도 효과가 없었다**(실험 42회). 답은 더 뽑는 것뿐이다.
효과: 미달률 **14.16% → 1.23%**.

**이름 오인식은 길이로 가린다.** 성경 고유명사를 ASR 이 못 알아듣는다(아담·셋·에노스 → Adam, Seth, Enos).
내용이 빠지면 자/초가 올라가므로 길이가 정상이면 받아쓰기가 틀린 것이다.
실측 11,076절: 중앙 6.74 · 99% 8.01 · 99.9% 9.23 자/초. 실제 누락 절은 10.8.
과거 120건 검증: 이름 절 115건이 풀리고, 진짜 결함 2건은 그대로 걸린다.
**숫자는 원인이 아니다** — 검수가 ASR 의 숫자를 한자어·고유어 두 가지로 되돌려 나은 쪽을 쓴다.

## 6. 알아야 할 구조

### 6.1 음원 키와 구방식 판정
- 음원 파일 이름이 곧 **정제 본문의 sha1** 이다 — `tts/v1/ko/{성우}/{sha1}.mp3`. 본문이 바뀌면 키도 바뀐다.
- **구방식** = 그 성우의 기준 시각(`LEGACY_BEFORE`, f4 는 2026-09-10T10:28:53Z) **이전**에 올라온 파일.
  예외로 시각이 새로워도 구방식으로 보는 해시 목록이 있다(`lib/voiceStudio/legacy.ts` `LEGACY_REUPLOADED`) —
  사고로 옛 음원이 다시 올라갔거나, 결함이 발견돼 덮어쓰기를 허용해야 했던 절들이다.

### 6.2 덮어쓰기는 두 길뿐이다
서버는 **새 방식 음원을 함부로 덮어쓰지 않는다**(`app/api/voice-studio/upload/route.ts`).

| 길 | 조건 |
|---|---|
| 구방식 교체 (`replace: true`) | 기존 파일이 **구방식일 때만** |
| 다시 만들기 요청 (`requestId`) | 관리자가 건 `verse-regen` 요청을 **그 PC 가 맡았을 때만** |

그래서 이미 새 방식으로 올라간 절을 다시 만들려면 **반드시 `verse-regen` 요청**을 거친다(웹의 '다시 만들기' 버튼,
또는 앱에서 절 선택 → '음원 다시 만들기'). 로컬 작업으로 다시 만들어 올려도 `exists` 로 무시된다.
요청은 PC 가 **10분마다** 확인하고, 하던 작업을 묶음 하나 끝낸 뒤 비켜 **먼저** 만든다(보통 15분 안).

### 6.3 다시 만들 후보
끝음절 값과 일치율은 **그 PC 의 작업 파일에만** 있다(서버는 모른다). 그래서 PC 가 세어 보고하고,
사람이 화면에서 눌러야 요청이 나간다. 조건은 `jobs.REWORK_KINDS` — 지금은 `short_end`(절 끝 짧음) 하나.
조건을 더하려면 거기에 한 줄 더하면 화면에 저절로 나타난다.

> '검수 기준에 못 미치는데 합격' 조건은 **뺐다**. 표본이 전부 이름 오인식이었고, 대부분 **이미 사람이 '이대로 사용' 으로
> 판단한 절**이었다 — 사람이 정한 것을 다시 묻는 목록이었다.

### 6.4 보류 절
검수에 걸려 **올라가지 않은** 절. 사람이 `이대로 사용` 을 눌러야 올라간다. 판단 결과는 PC 가 10분 안에 받아 간다.
'다시 만들 후보' 와는 **다른 목록**이다(그쪽은 이미 올라간 절).

### 6.5 자동으로 일어나는 일
- **이어가기**: 켤 때 멈춤·오류 상태의 작업을 다시 큐에 올린다(뒤에서).
- **다른 PC 가 만든 절 건너뛰기**: 책이 바뀔 때마다 서버에 이미 있는 절을 묻는다(여러 권 든 작업도 겹치지 않는다).
- **오류 회복**: 오류로 멈춘 작업을 다시 올리고, 그래픽 오류면 스스로 다시 켠다.
- **코드 갱신**: 30분마다 소스 지문 비교 → 다르면 다시 켠다.
- **기어가는 배치 감지**: 절당 180초 초과 → 배치 반으로.
- **메모리 부족**: 배치 반으로 → 1 → 검수 CPU 로.

## 10. 새 성우로 성경 전체를 만들 때

> ⚠ **흔한 오해**: 스튜디오 `3. 음원` 탭에서 등록하면 **그 PC 에만** 저장된다. 서버로 올라가지 않고, 성우 슬롯도
> 정해지지 않는다. 서버에 올리고 슬롯을 정하는 것은 `push_voice.py` 이며 **관리자 로그인 쿠키**가 필요하다
> (목소리 복제 데이터라 기기 토큰으로는 안 된다). 설치 화면에 슬롯 지정 기능은 **없다**.

1. **목소리 등록 (한 PC)** — 스튜디오 `3. 음원` 탭. 참조 음원 10~30초, 참조 텍스트는 *원문 넣기* 권장
   (받아쓰기 오인식이 섞이면 목소리가 흐려진다).
2. **성우 칸 열기 (코드)** — `lib/tts/verseText.ts`:
   - `PREGENERATED_VOICE_KEYS` 에 칸 추가(예: `["f4", "f5"]`) — 업로드·진도·보류가 모두 이 목록으로 막혀 있다
   - `PREGENERATED_VOICE_NAMES` 에 이름 추가
   - 옛 방식 음원이 없는 새 성우이므로 `LEGACY_BEFORE` 에는 넣지 **않는다**
   - push 하고 배포를 기다린다(3번이 이 목록으로 검사한다)
3. **서버에 올리고 슬롯 정하기 (한 번)** — 목소리를 등록한 그 PC 에서:
   ```bash
   cd C:\dev\yebomcard\voice
   python push_voice.py --voice 이름 --voice-key f5 --gender female --session <쿠키값>
   ```
   쿠키값: 브라우저로 예봄성경에 **관리자로 로그인** → 개발자도구 → 애플리케이션 → 쿠키 → `saint_record_session` 의 값.
   **이 값은 로그인 자격이다** — 대화 기록에 남기거나 커밋하지 않는다. 쓰고 나면 로그아웃해 무효화하는 편이 안전하다.
4. **다른 PC 는 켤 때 저절로 받아 간다**(`bootstrap.sync_voices`) — 클립을 PC 마다 다시 자르면 음색이 미묘하게 달라져
   책마다 목소리가 바뀐다. 반드시 서버의 같은 파일을 쓴다.
   각 PC 스튜디오 `3. 음원` 탭의 보이스 정보에 `성우 슬롯 f5 — 만든 절이 예봄성경으로 올라갑니다` 가 떠야 한다.
   **`[주의] 성우 슬롯이 없습니다` 가 뜨면 만들어도 안 올라간다.**
5. **교인에게 내보내기 (코드)** — `app/api/tts/route.ts` `KOREAN_VOICE_CONFIG` 에 `pregenerated: true` 로 두고,
   성우 목록(`contexts/TtsContext.tsx` `KOREAN_VOICE_ORDER`)에 넣는다. 음원이 다 되기 전에 넣으면 없는 절은 대신 읽기로 나간다.
6. **일 나누기** — 현황 화면 `책 맡기기`(성우 선택칸은 사전 생성 성우가 둘 이상일 때 저절로 생긴다).
   `queue` 명령에는 `--voice 이름` 을 준다.
7. **새 성우는 처음부터 새 방식이다** — 끝음절 교체 같은 뒷일이 없다.
